## 一、核心架构

### 0. 提效优先原则

本 skill 的首要目标是提升研发协作效率、减少用户重复说明和流程操作。AI 必须主动承担需求识别、上下文读取、模块归属判断、方案取舍、代码落点选择、验证和记忆沉淀工作。

除非命中第四章门禁判定表的"问一个问题"或"必须确认"档位，否则不得把"先生成方案再等用户确认"作为默认流程。信息足够时，先简短说明理解、落点和执行路径，然后直接推进。

### 1. 全局技能职责

1. 识别当前工作区是否属于已初始化项目。
2. 根据自然语言判断任务类型、风险等级和内部工作模式。
3. 调度合适的子技能或内置流程。
4. 按第三章分级读取表读取项目级记忆包。
5. 判断代码修改落点和模块归属。
6. 工作闭环结束后自动沉淀有效记忆。
7. 最终回复前执行必要验证。

全局 skill 不得保存项目专属业务记忆，不得把某项目的代码风格、业务规则或历史结论固化为跨项目默认规则。

### 3. 研发闭环与证据层

每项研发任务按“任务识别 → 风险判断 → 记忆读取 → 需求/方案 → 执行 → 验证 → 交付 → 证据记录 → 经验沉淀”推进。低风险任务可以使用缩短路径，但不得省略与风险匹配的验证和结果说明。

证据层只记录任务边界内的事实，不把规则存在误判为规则已执行。任务结果应能说明实际变更、验证动作、验证结果和未验证范围；没有观察到的行为保持未知，不凭推断补齐。

### 2. 项目级记忆包

每个项目的记忆默认放在项目根目录 `.codex-project/` 下：

```text
.codex-project/
  project-config.json    # 项目名、根目录、初始化状态、模板版本、模块清单、记忆文件路径
  project-memory.md      # 轻量索引与最近摘要，不承载完整业务记忆
  memory/
    static-memory.md     # 技术栈、编码规范、验证命令、公共约束、开发环境
    module-map.md        # 模块职责地图：类型、职责、边界、依赖关系
    business-memory.md   # 核心业务规则、表结构、接口契约、状态流转、权限规则
    iteration-memory.md  # Bug 根因、修复经验、UI 微调规律、踩坑记录
```

AI 不主动提交这些文件，不主动修改 `.gitignore`；用户明确要求纳入版本管理时才协助处理。记忆内容不得保存密码、token、账号、生产敏感地址或隐私数据。
