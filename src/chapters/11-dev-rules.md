## 十一、前后端开发规则

记忆读取统一按第三章执行；追问与确认统一按第四章执行。本章只定义开发特有规则。

### 1. 前端开发

1. 识别前端模块落点；落点不明且影响公共能力边界时按档二处理。
2. 查找同类页面、组件、请求封装、状态管理、样式和国际化写法。
3. 低风险样式微调可直接执行。
4. 涉及页面行为、接口入参、状态流转、权限显示时先识别规则；规则缺失、冲突或影响业务结果时按档二处理。

### 2. 后端开发

1. 判断接口属于业务模块还是公共模块；查找已有 controller、service、cmd、query、mapper、DTO、测试结构。
2. 公共能力变更属档三必须先确认；涉及业务状态、版本、审批、权限、事务时必须领域建模。
3. 不得把业务编排下沉到公共模块。

### 3. 跨前后端联动

必须核对：前端展示和操作入口、后端接口契约、入参出参错误处理、权限和按钮显示规则、历史数据兼容、验证方式。信息足够时直接推进，命中档二硬停条件时才确认。

### 4. 技术迁移与基础能力替换

涉及搜索引擎、缓存、消息队列、数据库、对象存储、认证、文件服务、第三方 SDK 或其他基础能力替换时，默认按高风险任务处理，并先产出端到端架构流程拆解或轻量迁移方案。方案必须核对：

1. 现状使用范围：调用入口、封装层、配置项、数据结构、定时任务、监控告警和部署依赖。
2. 兼容性差异：客户端 API、协议、查询语法、数据模型、事务/一致性语义、插件能力、错误码和性能特征。
3. 改造边界：只改配置、替换依赖、改造封装层、重写业务查询、重建数据结构或调整部署拓扑。
4. 数据策略：全量迁移、增量同步、双写、双读对比、停机窗口、历史数据回填和数据校验。
5. 发布策略：配置开关、灰度、回滚、监控指标、告警阈值、旧能力保留期和下线条件。

如果用户要求直接开发，且迁移影响范围清晰、已有同类实现和回滚方式明确，可以在简述迁移链路后推进；否则先输出方案并只问一个影响结果的关键问题。
