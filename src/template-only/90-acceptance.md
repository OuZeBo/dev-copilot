## 生成产物验收规则

使用本模板创建或更新 `dev-copilot` 全局 skill 后，必须执行产物验收（`node scripts/validate.mjs`），全部通过后才能提示创建或修复完成。验收脚本覆盖以下全部条目；脚本之外的条目由 AI 逐项核验。

### 1. 全局 skill 文件验收

必须检查 `skills/dev-copilot/SKILL.md`：

1. frontmatter 中 `name` 必须为 `dev-copilot`。
2. frontmatter 中 `version` 必须为本模板版本号。
3. 必须包含"提效优先原则"或等价规则。
4. 必须包含"自然语言自动触发"与"分级读取表"或等价规则。
5. 必须包含"统一门禁判定表"或等价规则，且包含三档互斥与硬停条件枚举。
6. 必须包含"`/init` 初始化扫描流程"或等价规则。
7. 必须包含"复杂需求协作分流"或等价规则，且为"声明路径直接推进、用户可打断"模式。
8. 必须包含"原型产物规则"或等价规则。
9. 必须包含"模块归属判断"或等价规则。
10. 必须包含"自动记忆策略"与"记忆体量控制"或等价规则。
11. 必须包含"子技能调度规则"与调度去重规则。
12. 必须包含"负向触发规则"或等价规则。
13. 必须包含"验证输出摘要"或等价规则。
14. 必须包含证据状态、Task Episode、完成前自检、只读审计、重复问题发现和反馈路由规则。

### 2. 元数据与规则唯一性验收

1. `version`、`dependencies` 等元数据只出现在 frontmatter，正文不得重复定义。
2. 记忆读取规则只在"分级读取"章节完整定义，确认与追问规则只在"统一门禁判定表"章节完整定义，其他章节仅引用，不得出现重复定义。
3. `SKILL.md` 必须由 `src/` 源文件组装生成，不得直接手工编辑；源文件中同一条规则只存在于一个章节文件。

### 3. 依赖完整性验收

1. frontmatter `dependencies` 中每一项必须在 `skills/` 目录存在对应技能副本。
2. `grilling` 作为 `grill-me` 的传递依赖，必须在 `skills/` 中存在，但不在 dependencies 中声明。
3. 部署到目标环境后，目标技能目录必须包含 dependencies 全部条目及 `grilling`。

### 4. 项目中立验收

全局 `dev-copilot` skill 不得包含具体项目事实。创建或更新后必须搜索并清理：具体项目名称、路径、模块名、业务域名称、接口、表结构、字段、历史需求结论，以及从某个项目提取的代码风格或业务规则。

如果需要举例，必须使用通用模块名，例如 `backend-core`、`backend-business`、`frontend-app`、`shared-library`、`supporting-artifacts`。具体项目事实只能写入该项目自己的 `.codex-project/`。

### 5. 配置文件验收

必须检查 skill 目录下 `agents/openai.yaml`：

1. `display_name` 应为"项目研发助手"。
2. `short_description` 应体现跨项目研发调度、初始化、自然语言触发和项目级记忆。
3. 必须允许隐式触发。

### 6. 文档质量验收

1. 不得存在未完成标记、未定说明或空模板内容。
2. 不得存在不连续或重复编号的有序列表。
3. 不得存在旧版本目标规则残留，例如把本版本目标写成旧版号。
4. 不得存在"创建 skill 时还需要后续手动修复"的说明。
5. 模板与 `SKILL.md` 均由构建脚本生成，不得丢失本章列出的关键规则。

### 7. V2.1 专项验收

1. `configured`、`observed`、`verified`、`failed`、`unobserved`、`deferred` 六种状态含义明确，且未观察行为不得被推断为成功。
2. Task Episode 至少包含目标、风险级别、模块落点、实际变更、验证动作、验证结果、未验证范围、剩余风险和经验沉淀。
3. 审计模式默认只读，只在用户明确要求时触发，低风险任务不启动完整审计。
4. 反馈路由能区分全局规则、项目配置、业务记忆、迭代记忆和模块地图。
5. V2.1 不新增 Better Harness 依赖、插件、CLI、会话采集器或外部上传流程。
